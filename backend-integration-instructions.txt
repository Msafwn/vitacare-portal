          LIFEDROP DONOR PORTAL - BACKEND INTEGRATION GUIDE
================================================================================

1. ANALYSIS: IS IT EASY TO INTEGRATE A BACKEND?
--------------------------------------------------------------------------------
Yes! Backend integration is now extremely easy. 
We have successfully converted your frontend to use React Router, Axios, and 
Redux Toolkit (RTK). This means the frontend is already decoupled and "MERN-ready". 

To connect a backend, you only need to:
  1. Build your Express + Node.js server.
  2. Point the frontend Axios instance to your server's URL.
  3. Replace the mock data with Redux RTK hooks.

--------------------------------------------------------------------------------
2. MONGOOSE MODELS TO CREATE (BACKEND)
--------------------------------------------------------------------------------
In your Node.js/Express backend, create the following 5 models:

A. User Model (Covers Donors, Recipients, and Admins)
   Fields: name, email, password (hashed), phone, bloodGroup, city, address, 
           role (Donor/Recipient/Admin), status, available, totalDonations, joined.

B. Admin Model (For completely separate admin accounts)
   File path: `models/Admin.js`
   ```javascript
   import mongoose from 'mongoose';

   const adminSchema = new mongoose.Schema({
     name: { type: String, required: true },
     email: { type: String, required: true, unique: true, lowercase: true },
     password: { type: String, required: true }, // Hashed
     accessCode: { type: String }, // For 2FA / Authenticator app simulation
     permissions: [{ type: String }], // Array of specific permissions
     lastLogin: { type: Date }
   });

   export default mongoose.models.Admin || mongoose.model('Admin', adminSchema);
   ```

C. BloodRequest Model
   Fields: patient, bloodGroup, units, hospital, city, neededOn, urgency, 
           status (pending/approved/fulfilled), requester (ObjectId ref to User), notes.

D. Donation Model
   Fields: donor (ObjectId ref to User), bloodGroup, units, center, city, date, status.

E. Notification Model
   Fields: user (ObjectId ref to User), title, body, time, type, unread (Boolean).

F. Inventory Model
   Fields: group (Blood group), units, capacity, updated.

3. WHERE TO MAKE CHANGES IN THE FRONTEND
--------------------------------------------------------------------------------

You will need to modify the following specific files in your frontend to complete 
the integration:

A. Configure API Connection
   - File: `src/lib/axios.js`
   - Change: Update `baseURL: 'http://localhost:5000/api'` to your actual 
     Express server port and URL.

B. Define API Endpoints
   - File: `src/store/apiSlice.js`
   - Change: Add all your endpoints inside the `endpoints: (builder) => ({ ... })` 
     block. For example, add `login`, `getDonors`, `createRequest`, etc.

C. Update Authentication Guards
   - File: `src/components/auth/AdminProtectedRoute.jsx`
   - Change: Currently it checks `localStorage.getItem("adminToken")`. Update this 
     to check your Redux store state (e.g., `useSelector(state => state.auth.isAdmin)`).
   - File: `src/routes/admin.login.jsx` and `src/routes/login.jsx`
   - Change: Replace the mock `onSubmit` function to fire the RTK `loginMutation`.

D. Replace Mock Data in UI Pages (src/routes/*.jsx)
   You must remove `import { ... } from "@/data/mock"` and use RTK Hooks instead in:
   - `src/routes/dashboard.jsx`: Fetch user stats and recent history.
   - `src/routes/find-donors.jsx`: Fetch active donors from DB based on city/blood group.
   - `src/routes/requests.index.jsx`: Fetch all open blood requests.
   - `src/routes/donations.jsx`: Fetch user's donation history.
   - `src/routes/notifications.jsx`: Fetch notifications via API.
   - `src/routes/admin.dashboard.jsx`: Fetch aggregated stats for the admin charts.

4. ADMIN SIDE BACKEND (API & SECURITY)
--------------------------------------------------------------------------------
The admin side uses the exact same database (MongoDB), but the API routes require 
special security to ensure normal users cannot access admin data.

A. Admin Middleware (Backend)
   In your Express.js server, create a middleware that checks if the logged-in 
   user has the Admin role:
   ```javascript
   export const adminProtect = (req, res, next) => {
     if (req.user && req.user.role === 'Admin') {
       next();
     } else {
       res.status(403).json({ message: 'Not authorized as an admin' });
     }
   };
   ```

B. Admin API Endpoints
   Protect your admin routes using this middleware:
   - `GET /api/admin/stats` -> Fetch total users, donations, and requests.
   - `GET /api/admin/users` -> Fetch all users.
   - `PUT /api/admin/requests/:id` -> Approve or reject requests.
   - `PUT /api/admin/inventory` -> Update blood stock manually.

C. Admin Frontend Changes
   In `src/store/apiSlice.js`, add admin-specific RTK hooks:
   - `useGetAdminStatsQuery()`
   - `useUpdateInventoryMutation()`
   Call these inside your `admin.dashboard.jsx` and `admin.inventory.jsx` files.
